# Responsive landing hero

Layer by layer now follows the Explore the possibilities model-concept section. The MAKERS3D collection remains ahead of those sections, with its component, images and typography preserved.

At 1024 px and above, the vase plays automatically like a video while the whole page, including the headline and description, scrolls normally. The 9.7-second print and photo reveal plays once, then leaves the finished photograph in place and unmounts the WebGL canvas. Playback pauses while the visual is offscreen or the browser tab is hidden. Completion stays in document memory across scrolling, viewport changes, browser document restores, and client-side navigation away and back. A full page refresh starts it again.

Below 1024 px, the order is headline, vase, then description and actions. Scrolling advances the print while a native sticky wrapper holds the visual below the navigation. Idle time does not advance it. The finished photo remains fully visible at completion, with a short hold before it scrolls out and the lower content comes up. The wrapper retains its space, so completion never changes the page's scroll position. The landing page body uses horizontal clipping instead of a hidden overflow scroll container to allow native sticky positioning.

Mobile completion stays in component memory for that visit and unmounts the WebGL canvas. Scrolling back keeps the finished image. Reloading, navigating away and returning, or restoring a browser document starts a fresh mobile sequence. Resizing a completed sequence keeps the finished image. No cookies or browser storage are used for completion.

Reduced motion and unavailable WebGL show the photograph directly. A context loss during a mobile print reveals the photo without collapsing the wrapper or moving the page. The original text animation controller and product collection are unchanged.

Temporary preview files and documentation are excluded from [Tailwind source detection](https://tailwindcss.com/docs/detecting-classes-in-source-files). This prevents active browser profiles and generated review files from repeatedly rebuilding the development stylesheet. Application sources remain within the project root.

TypeScript, component lint, and whitespace checks pass. Browser checks cover phone and laptop layouts. Laptop text and visuals move with ordinary page scrolling while playback advances automatically. Mobile checks confirm headline placement, no idle advancement, the photo blend, a fully visible finished image, unchanged scroll position at completion, and natural movement into the content below. Scrolling back preserves the photo. Mobile client navigation back restarts; desktop client navigation back keeps the completed photo. Reload starts a new animation. Earlier checks covered reduced motion, a simulated persisted pageshow, and actual WebGL context loss.
